# 话题汇总设计方案

状态：首版已实现。离线回填、同步关联、话题列表与详情、人工分类和专栏关联、AI 整理任务已接入。真实账号数据规模仍需在用户资料库验证。本文中的“话题”指知乎问题页（`/question/{id}`）；现有“大类 / 小类”仍指知微的本地主题分类。

## 目标与现状

把文章库中**有可验证问题归属**的内容按知乎问题 ID 汇集：同一问题只出现一次，展示该问题下已收藏的回答，并给问题本身分配本地主题分类。用户可以搜索问题、按分类浏览、打开知乎原问题和本地回答。

当前库的盘点快照为 778 条内容，其中 501 条回答可提取问题 ID，合并后为 453 个不同问题；另有 277 条知乎专栏文章没有已保存的问题归属。这些数字会随同步变化。现有阅读页已能从回答 URL 和 `metadata.json` 得到问题链接，但数据库没有独立的问题表，也没有话题列表。

以“假如LLM无限上下文了，RAG还有意义吗？”为例，回答 URL 中的 `653424464` 对应唯一的话题记录 `https://www.zhihu.com/question/653424464`。同一问题的多篇已收藏回答列在该记录下。

## 收集规则

1. 对 `kind=answer`，沿用阅读页的可信提取规则：校验 HTTPS、`www.zhihu.com` 域名、`/question/{问题ID}/answer/{回答ID}` 路径，并确认回答 ID 与本地 `remote_id` 一致；也可使用格式正确的已保存 `metadata.question.id`。两处 ID 冲突时以经校验的回答 URL 为准，记录异常供排查，不采用冲突的元数据标题。
2. 以问题 ID 去重，问题 URL 在本地由 ID 构造。标题优先取 ID 一致的 `metadata.question.title`，否则使用回答标题。绝不把元数据里的任意 URL 直接作为外链。
3. 专栏文章只有在来源数据明确给出所属问题，或用户手动指定问题 URL 时才建立关联。正文中提及问题、标题相似或模型认为“相关”，都不足以证明“属于该问题”。没有归属的专栏文章继续留在文章库，不计入话题数。
4. 首次启用时离线回填已有回答；以后每次成功保存回答时更新问题及关联。重复运行应得到相同结果，不依赖再次访问知乎，避免登录和风控影响本地汇总。

## 数据设计

新增 `questions`：`id`（知乎问题 ID，主键）、`title`、`url`、`category_id`（可空，引用现有叶子分类）、`classification_source`（`model` / `manual`）、`classification_locked`、`classification_reason`、`classified_input_hash`、`created_at`、`updated_at`。未归类使用 `category_id=NULL`，界面显示“待整理”。分类删除时置空。

新增 `question_contents`：`question_id`、`content_id`、`link_source`（`answer_url` / `answer_metadata` / `manual` 等）、`created_at`；以 `(question_id, content_id)` 为主键，两个外键级联删除。列表中的回答数实时统计关联记录，不存冗余计数。人工关联专栏文章时保留 `manual` 来源，界面明确标出；回答和专栏文章在详情页分组展示。

迁移应创建表和索引，并用已有回答分批回填。逐条失败只记录问题和原因，不中断整个回填；重试可继续。同步写入内容与问题关联时尽量使用同一数据库事务；如果文件与数据库提交之间异常，启动修复或下次回填可以重建关系。删除内容时关联自动清除；没有本地内容的问题记录可清理，人工维护的问题记录则保留并显示“暂无本地内容”。

## 归类方案

话题分类独立于回答分类。原有文章分类曾有误分，不能直接把回答的分类复制成问题的最终分类；同一问题下的多篇回答也可能属于不同本地分类。

收集完成后执行可中断、可重试的“整理话题”任务。给已配置的 AI 模型发送问题标题及关联回答的有限长度摘要，并附当前有效的叶子分类 ID 和名称；单个问题只处理一次，输入变化后才允许重新建议。模型返回分类 ID、简短理由及是否有把握，后端验证分类存在且为叶子节点。无把握、模型不可用或调用失败时保留“待整理”并展示原因。任务限制并发、记录进度和逐项失败，避免对数百问题同时发起请求。

用户可以手动选择分类或清空分类。手动结果设为锁定，后续同步和自动整理不得覆盖。提供“重新建议分类”操作，仅在用户明确操作时解除或绕过该问题的锁定。问题分类变化不改动关联文章的分类；文章分类变化也不自动改动已确认的问题分类。

## 页面与接口

侧栏增加“话题汇总”。列表显示问题标题、完整分类路径、已收藏回答数、关联专栏文章数和整理状态；支持关键词、分类、“待整理”筛选及分页。详情页显示知乎问题链接、该问题下的本地回答与人工关联的专栏文章，每条可进入阅读页；展示归属来源及人工分类入口。话题列表的数量以问题数为单位，不能与文章库条数直接比较。

建议接口：

- `GET /api/v1/questions`：分页、搜索、分类和状态筛选。
- `GET /api/v1/questions/{id}`：问题信息与关联内容。
- `PATCH /api/v1/questions/{id}/classification`：手动设置或清空分类。
- `POST /api/v1/question-collection/backfill`：幂等回填和修复旧数据。
- `POST /api/v1/question-classification/jobs` 与 `GET /api/v1/question-classification/jobs/{id}`：启动整理、查询进度和失败项。
- `POST /api/v1/questions/{id}/contents`、`DELETE /api/v1/questions/{id}/contents/{content_id}`：仅供手动关联或解除专栏文章，校验问题 ID、内容存在及关联来源。

## 实施顺序与验收

1. 增加数据库迁移、提取和回填服务；复用现有阅读页的问题 ID 校验逻辑，避免两套规则分叉。
2. 把新回答的关系更新接入同步流程，并提供列表、详情接口。
3. 实现话题页面、人工归类和专栏文章人工关联。
4. 接入 AI 整理任务及进度、失败重试，最后补齐使用文档。

验收以当前库快照为例：回填后应约有 453 个问题、501 条回答关联；重复回填不增生记录；问题 `653424464` 只出现一次，知乎链接正确且能打开关联的本地回答。277 条无明确归属的专栏文章不能因标题相似被自动挂靠。人工锁定的分类在同步和重新整理后保持不变；模型返回不存在的分类、调用失败或判断不确定时，页面能明确显示待整理或失败状态。

首版的“汇总”侧重收集、去重、归类及关联内容导航。跨多篇回答的生成式观点摘要可以后续增加，但必须以本地回答为依据并标出引用，不能把生成内容当作知乎问题原文。


## 当前实现与使用

服务启动时自动离线回填已有回答，也可在“话题汇总”点击“回填已有回答”修复关联。回答保存成功后更新对应话题；专栏文章只通过输入标准知乎问题链接及本地文章 ID 手动关联。话题页提供问题搜索、分类与待整理筛选，详情页展示已收藏回答和人工关联文章。

“整理话题”调用设置中的聊天模型，逐个提交问题标题与最多五篇本地回答摘要，并验证模型返回的分类 ID 是现有叶子分类。无把握时保留待整理；请求失败可在任务结束后重试失败项。人工分类（含清空）会锁定该话题，自动任务不会覆盖。点击“重新建议分类”会解除该话题锁定并让下次整理任务重新处理。

本地验证：`python3 -m pytest -q backend/tests/test_questions.py` 覆盖回填幂等、冲突标题、人工关联与分类锁定；`cd frontend && npm run build` 验证页面编译。当前资料库中的 453/501 快照需在原数据目录下运行后核对，测试夹具不包含私人文章。
