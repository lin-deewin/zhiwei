# 检索、知识链接与持续研究

## 1. 先检索，再核对效果

在左侧「知识问答」输入问题，选择分类和资料类型，点击「查找资料」或「根据资料回答」。文章、个人笔记、高亮批注、已保存研究笔记和主题知识页可统一检索；未保存草稿不参与。

展开「语义检索与效果验证」可建立或更新本地索引、查看进度、取消后续计算。默认模型是 `BAAI/bge-small-zh-v1.5`，第一次需要下载；此后向量计算在后端机器上运行。已有索引每两分钟检查资料新增、修改与删除。模型不可用、索引未建立或更换模型后尚未重建时，检索回退到关键词。

关键词采用中文双字切词、同义词扩展和 BM25，语义检索按向量相似度召回，再融合两个排名、去重并优先覆盖不同资料。结果标明语义或关键词匹配。长段落先切片再排序；当前有效片段校验会过滤旧版本和已删除资料。

评测方法：

1. 输入一个日常会问的问题，勾选应该找到的正确资料。
2. 如果正确资料未出现在结果中，在「知识空间」资料目录找到它的稳定 ID，并填入「补充正确资料 ID」。可以标注未被召回的资料，避免只评测已经命中的结果。
3. 加入评测集，积累不同问法，包括同义表达、短问题、易混淆话题和需要多份资料的问题。
4. 点击「运行对比评测」，对比前五个片段的 Recall@5（正确资料的召回比例）和 MRR（第一个正确来源的排名得分）。

评测只代表这些人工标注问题，不能当作所有回答的准确率。标签应经过核对，最好保留一部分问题用于独立验证。

## 2. 多份资料生成带出处的笔记

检索后勾选至少两份不同资料、最多十六个片段，点击「生成带出处的研究笔记」。同一篇文章的两个片段不算两份资料。核对草稿、修改标题和正文，再保存。保存后可在「我的笔记」或「知识问答」下方打开，并继续参与检索。

`[S1]` 等编号对应实际发给模型的证据片段。来源类型、记录 ID、内容指纹和生成时正文随笔记保存，原文修改或删除不会改变历史快照。点击「查看当前资料」看到的是当前版本，可能与当时不同。

在编辑器下方的「版本历史」选择旧版本，查看与当前已保存版本的差异，并可恢复为一个新版本。恢复不会清空历史，但会替换编辑器内容；请先保存尚未保存的修改。Markdown 外部导入导致的研究笔记修改也记录版本。

## 3. 双向链接与主题知识页

打开左侧「知识空间」的「主题与链接」：

- 创建主题页并编辑 Markdown，可以组织概念、结论、争议和待验证问题。
- 在资料目录选择最多十六份资料，点击「用所选资料生成更新草稿」。草稿先供审阅；放入编辑器并保存后才更新主题页。证据快照同时保存。
- 资料目录中的勾选框用于 AI 整理；点击某份资料旁的「插入双向链接」，会将该资料链接追加到下方 Markdown 正文并定位编辑器。点击「保存主题页」后链接才正式生效。也可手写 `[[唯一标题]]`、`[[article:ID|显示名称]]`、`[[note:ID|显示名称]]`、`[[research:ID|显示名称]]`、`[[topic:ID|显示名称]]`。
- 已解析的正文链接可以点击。在阅读页、研究笔记和主题页的「知识链接」区域查看关联资料和反向链接，也可直接建立显式链接。

同名标题不会自动猜测目标；使用目录中的稳定 ID 消除歧义。缺失目标会提示。代码块中的示例不建立知识链接。主题页和研究笔记的证据引用也产生来源关联。

## 4. Markdown 与 Obsidian 互通

在「知识空间 → Markdown 互通」设置**后端机器**上的独立目录，默认是当前资料库下的 `Obsidian` 文件夹。把此目录作为 Obsidian Vault 打开即可。

首次点击「导出全部资料」：文章、笔记、批注评论、已保存研究笔记和主题页按类型及稳定 ID 写成 `.md`；文章本地图片复制到 `assets/`，知识链接转换为 Vault 文件路径。YAML 中保留 `zhilib_source`、`zhilib_library`、标题、作者、来源地址等；研究证据保存在 `.zhilib/evidence/`。使用 Obsidian 时保留这些字段及隐藏目录。

外部新增或编辑文件后：

1. 点击「扫描外部变化」查看预览。
2. 勾选新文档和外部修改，点击「导入所选变化」。新文件作为本地文章导入；已有文件按稳定 ID 更新。
3. 本地与外部同时修改时，系统保留双方，不自动覆盖。先在外部文件中完成合并，再点击「已人工合并，备份双方后导入」。双方正文备份存入 `.zhilib/conflicts/`；预览后再次变化会拒绝导入。
4. 可开启每两分钟同步无冲突变化。外部删除不会删除本地资料；同一 ID 的重复文件必须先处理，不允许强行导入。

导入要求：UTF-8/UTF-8 BOM，单个 Markdown 不超过 10 MB；YAML 可省略，支持 `title`、`author`、`source_url` 或 `url`。标题优先 YAML、其次首个一级标题、最后文件名。标准 Markdown 图片引用支持 Vault 内 PNG/JPG/JPEG/GIF/WebP/AVIF，单图不超过 20 MB；网络图片保持链接。越界路径、符号链接和来自其他资料库的稳定 ID 会拒绝或提示。无元数据的新文件由同步清单追踪，重复扫描不重复导入；内容和附件未变的重命名可以识别。建议先完成一次扫描/导入，再做下一批外部修改。

此功能提供 Markdown、YAML、标准图片和双向链接互通，不负责执行 Obsidian 插件、Dataview 查询、Canvas 或专有嵌入语法。多设备并发编辑仍需自行选择文件同步工具并处理冲突。

## 5. 持续研究工作区

在「知识空间 → 持续研究」创建项目：填写名称和研究主问题，搜索并勾选最多十六份资料，保存项目。

- 证据集按主问题在所选资料中挑选相关片段，包含文章后半部分。初次保存后形成固定快照。
- 「基于证据集追问」利用最近四轮对话理解指代，事实仍须来自已保存证据；每轮回答保存自己的出处快照。
- 可以追加或移除资料，再点击「保存证据集选择」。已有资料快照保持不变；「刷新为当前原文」会显式重新提取当前证据，历史回答不会被改写。
- 「生成新的研究笔记」生成待审阅草稿，在「研究成果」中点击打开、编辑、保存。一个项目可持续产生多篇成果。
- 刷新页面或重启后端后，重新打开项目即可继续。模型生成期间证据集或对话被其他操作修改时，本次结果不写入，避免串用版本。

## 模型与出处的实际限制

问答候选超过十个时可调用聊天模型重排，最多等待 35 秒，失败后保留本地排序。回答和研究正文的证据总量约 8,000 字符；超长片段按问题节选，快照保留模型实际使用的内容。研究项目保存的证据集预算约 16,000 字符，每轮请求再节选至生成预算。

生成会将选定片段发送给配置的聊天模型。OpenCode 使用独立运行进程加载禁止工具操作的知识库配置，单次请求最多 240 秒，整体知识请求最多 330 秒。模型服务仍可能限流、认证失败或超时，界面显示具体类别。

系统检查引用编号，无效时要求模型重写一次。编号有效不代表结论被原文支持；个人观点、文章观点和 AI 整理应分开核对。研究笔记引用其他 AI 整理时，仍需沿链接检查原始来源。
