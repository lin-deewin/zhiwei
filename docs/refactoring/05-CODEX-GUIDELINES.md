# Codex 执行规范（Zhiwei V3）

## 开始任务前
1. 阅读仓库根目录 AGENTS.md 和对应重构文档。
2. 读取任务依赖和当前分支状态。
3. 检查现有实现，先复用，再抽象，最后才新增。
4. 明确数据/API/安全影响和回滚办法。
5. 若需求与章程冲突，先提出冲突，不自行扩大范围。

## 编码约束
- Python 使用类型标注、4 空格缩进，遵守 Ruff。
- TypeScript 保持 strict，2 空格缩进。
- UI 使用已有 React/TypeScript 技术栈；不随意引入 UI 框架。
- 页面、领域服务和基础设施分层，不把新业务继续堆进 App.tsx。
- 不在组件内复制 API 请求和业务规则。
- 统一处理 loading、empty、error、success 和 pending 状态。
- 不为视觉装饰牺牲正文空间、可读性和可访问性。
- 外部文章 Markdown 与用户笔记分开持久化。
- 不自动创建文章间知识链接。
- AI 引用必须由后端校验，不信任模型自报来源 ID。

## 数据与安全
- 未经明确迁移设计，不修改既有数据结构。
- 数据库变更必须包含可重复迁移测试。
- 不覆盖用户编辑过的 Markdown。
- 不在日志、提交或测试夹具中写入 Cookie、API Key、私人文章全文。
- 访问本地文件必须验证资料库根路径和符号链接边界。
- Markdown HTML 和 URL 必须安全清理。
- 任务必须支持超时、取消、重试和进程重启后的可观察状态。

## 每个任务完成前
1. 运行对应测试。
2. 运行前端构建或后端测试（按影响范围）。
3. 检查 diff，移除调试代码和无关改动。
4. 更新 API/架构/用户文档。
5. 报告实际测试结果，未运行的测试明确标注。
6. 不得声称未验证的功能已完成。

## Git 规范
- 在 refactor/v3 上开发。
- 小步提交，提交信息描述实际变更。
- 不 force push，不直接改写 main。
- 阶段完成后检查与 main 的 diff，并通过 PR 评审。
