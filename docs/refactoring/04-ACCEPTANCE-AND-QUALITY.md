# Zhiwei V3 验收与质量门槛

## 1. 产品验收
- [ ] 默认进入资料库首页，最近阅读和待阅读内容清晰可见。
- [ ] 外部文章与个人笔记在列表、类型、编辑权限和详情页中清楚区分。
- [ ] 阅读、收藏、批注不强制创建笔记或双向链接。
- [ ] 阅读位置可恢复；文章更新时不会错误跳转。
- [ ] 高亮、批注、笔记彼此独立。
- [ ] 个人笔记可引用原文，笔记间链接可查看反向链接。
- [ ] 文章之间默认没有自动双向链接。
- [ ] AI 结果可追溯到准确正文版本和证据。
- [ ] AI 未配置时本地核心能力正常。
- [ ] 研究证据历史不会因当前资料变化而被改写。

## 2. 数据安全验收
- [ ] 迁移前自动备份 SQLite。
- [ ] 迁移前后稳定内容 ID 一致。
- [ ] 文章 Markdown 与图片文件哈希一致（除明确的用户编辑外）。
- [ ] 高亮、批注、笔记、研究项目、知识链接数量与抽样内容一致。
- [ ] 用户修改的文件不会被静默覆盖。
- [ ] 删除笔记不删除来源文章。
- [ ] 失败迁移可恢复备份。
- [ ] 旧 API 消费者在迁移窗口内保持兼容。

## 3. 工程质量门槛
- 前端 TypeScript 检查和生产构建通过。
- 后端 pytest 全量通过。
- 数据迁移在空库、旧库、已迁移库上通过。
- 核心 API 有输入校验、错误语义和边界测试。
- 关键用户流程有集成或端到端验证。
- 不引入未使用依赖。
- 不新增明文凭据、Cookie 或私人正文日志。
- Markdown 渲染经过 sanitize；链接协议受限。
- 路径访问不能越过资料库根目录。
- 长任务可恢复，不依赖页面一直打开。

## 4. 性能验收建议
以生成的 1,000 篇文章测试集作为初始基准，记录：
- 资料库首屏加载时间
- 搜索响应时间
- 阅读页首屏渲染时间
- 100 个标签/大量笔记下的内存与交互表现
- 任务进度推送和重连恢复

先测量再优化，不把未经实测的毫秒数作为完成声明。对性能回归应与 E0 基线比较。

## 5. 发布门槛
只有 E0–E7 的 P0 项完成、关键回归通过、数据备份/恢复演练成功、部署健康检查通过，才可申请合并至 main。P1/P2 未完成项必须列入发布说明，不能伪装为已交付。
