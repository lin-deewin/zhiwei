# 知微（Zhiwei）全站界面与体验重构方案

**版本：** UX / UI Design Proposal V1.0  
**评审状态：** 已确认，正式开发以此设计与原型为基准  
**检查范围：** `lin-deewin/zhiwei`，2026-11-09 GitHub 可访问的 `dev` 分支  
**基准提交：** `d7df633d2e602a1b568b8146e4037d13f55f790d`  
**原型：** 本目录 `index.html`（不依赖网络，可双击打开）

> 这是根据仓库源码、用户文档和页面结构所做的界面审查。没有连接真实知乎账号、真实资料库或运行完整后台；真实数据、响应速度及各项 API 可用性仍需上线前验证。原型中的文章、统计数值和同步记录均为示例，不是现有用户数据。

## 1. 产品重新定位

**一句话定位：** 把分散收藏变成真正可阅读、可检索、可连接、可研究的个人知识空间。

关键用户路径：

1. **收集：** 知乎收藏 → 同步中心 → 可查看任务进度、错误与增量变化。
2. **阅读：** 文章库 → 高质量阅读界面 → 高亮、批注、AI 阅读与个人笔记。
3. **组织：** 主题目录 / 话题汇总 → AI 辅助整理 → 人工修正。
4. **连接：** 知识空间 → 双向链接文章、笔记与主题知识页。
5. **研究：** AI 研究 → 证据检索、引用、研究笔记保存与追溯。

**设计北极星：** 在不牺牲原有能力的前提下，减少用户“找按钮、找功能、找文章、找上一步”的成本，让每一屏只有一个主要任务。

## 2. 源码诊断与主要问题

### 已确认的项目结构

- 前端：React 19、TypeScript、Vite、React Router、Lucide React。
- 后端：FastAPI + SQLite；本文初期**不要求重写后端**。
- 主路由（当前源码）：`/` 文章库、`/read/:id` 阅读、`/questions` 话题、`/categories` 分类、`/ask` 知识问答、`/knowledge` 知识空间、`/notes` 笔记、`/sync` 同步、`/settings` 设置。
- `frontend/src/App.tsx` 约 65 KB，包含全局布局以及多个页面组件；`frontend/src/styles.css` 约 77 KB，全站样式高度集中；`WorkspaceTabs.tsx` 还单独管理工作标签与路由状态。
- 现有阅读工作区已涉及高亮、批注、笔记、AI 助手；知识空间包含双链、Markdown 互通、持续研究；这些能力须保留。
- 可访问的远程分支为 `main`、`dev`，当前两者指向同一提交。**本次未发现 `v2` 分支**，正式施工前应再次确认最新开发版本，避免在旧代码上改造。

### 信息架构和界面症结

| 层面 | 现状/风险 | 重构动作 |
| --- | --- | --- |
| 导航结构 | 主菜单、主题快捷入口、工作标签、页内操作区同时存在，入口层级不够统一 | 主导航按用户目标分组；主题在独立页面浏览，工作标签按需展示 |
| 页面骨架 | 各页标题、筛选、按钮区、卡片与表格构成方式不一致 | 统一 Shell / PageHeader / FilterToolbar / Content / ContextPanel |
| 按钮体系 | 样式分别散落于页面与全局 CSS，主次操作不够稳定 | 单页原则上只保留 1 个视觉主操作；其他为次级、文字或溢出菜单 |
| 阅读体验 | 阅读与管理动作混杂；上下文工具有竞争注意力的可能 | 编辑级阅读版心 + 可收起右侧上下文；按选区显示对应功能 |
| 模块组织 | `App.tsx` 同时承载布局与页面业务，CSS 大文件难独立维护 | 按功能路由拆分，建立可复用组件与设计 Token |
| 数据状态 | 同步、分类、研究涉及运行、失败、重试与留痕 | 制定统一进度、反馈、空态、错误、危险操作规范 |
| 视觉系统 | 字号、间距、色彩、边框和交互状态需要规范化 | 以 8px 体系与设计 Token 建立统一组件质量线 |

## 3. 新版信息架构（IA）

```text
知微
├── 我的工作台
│   ├── 概览（新：首页仪表台，只呈现最有价值的信息）
│   ├── 文章库（原 /；支持列表/卡片、检索、来源、排序、主题筛选）
│   ├── 话题汇总（原 /questions；按问题聚合已收藏回答）
│   └── 我的笔记（原 /notes；统一阅读笔记、个人笔记、研究笔记入口）
├── 知识探索
│   ├── 主题目录（原 /categories；分类管理、待整理队列）
│   ├── 知识空间（原 /knowledge；知识页、双链、项目、Markdown）
│   └── AI 研究（原 /ask；检索、回答、证据、研究历史）
└── 工具与偏好
    ├── 同步中心（原 /sync；知乎连接、全量/增量、任务历史）
    └── 偏好设置（原 /settings）

文章阅读：从文章库/话题/搜索结果进入，优先使用沉浸式阅读布局。
文章原路由 /read/:id 保留，兼容历史链接。
话题详情 /questions/:id 保留。
```

**新首页的价值：** 不是再增加一张大海报。顶部直接看到文章、主题、笔记、待整理四个轻量概况；首屏显示最近收录、常用主题和同步状态。用户最快一次点击直达目标。

**双层导航策略：** 左侧导航负责“去哪个工作区域”；页面顶部负责“当前任务与重要操作”；页内局部标签只负责“同类数据的视图切换”。不再同时让三套导航竞争主要注意力。

**工作标签策略：** 保留 `WorkspaceTabs` 的核心能力（多篇文章并行阅读、状态恢复），但默认不常驻空标签栏。仅当打开多个文档/研究任务时显示精简标签条，支持关闭、快捷键与恢复；不牺牲现有进阶用户工作流。

## 4. 全站布局规范

### 桌面版 1440 × 900 的布局

```text
┌──────────── 242px ┬─────────────────────────────────────────────┐
│ 知微              │ 64px 顶栏：面包屑 │ 全局搜索 │ 状态 │ 外观   │
│ 我的工作台        ├─────────────────────────────────────────────┤
│   概览            │  页面标题              重要操作（最多 1 个主按钮）│
│   文章库          │                                             │
│   话题汇总        │  筛选 / 子导航（仅需要时）                     │
│   我的笔记        │                                             │
│ 知识探索          │  内容 / 表格 / 知识页面，优先展示实际内容        │
│   主题目录        │                                             │
│   知识空间        │  特定任务右侧：按需出现的上下文面板              │
│   AI 研究         │                                             │
│ 同步中心          │                                             │
│ 偏好设置          │                                             │
└───────────────────┴─────────────────────────────────────────────┘
```

- 侧栏：242px，主要导航区密度一致；移动端改为可唤出抽屉。
- 顶部栏：64px；只显示位置、全局搜索、状态、外观，不安排大面积介绍区。
- 内容最大宽：1320px；左右留白在大屏不无限扩张。
- 阅读版心：正文区域目标在 650–760px 左右，正文 15–17px，行高约 1.9–2.1；旁注区为弹性 250px。
- 页面标题：24–28px，单行优先；面包屑及功能说明弱化。
- 卡片：默认只使用 1px 浅描边与低对比阴影，消除大量相同权重的“盒子套盒子”。
- 响应式：1440、1024、768、390 四档重点验收；手机操作目标建议 ≥44px。

## 5. 视觉系统与设计 Token

| 类型 | 规则 | 原型值 |
| --- | --- | --- |
| 主色 | 低饱和深松绿，形成知识阅读气质，不作大面积填充 | `#246B58` |
| 主文字 | 非纯黑的深色，避免刺眼 | `#212A27` |
| 次级文字 | 只承载说明、辅助元信息 | `#5F6A65` |
| 页面背景 | 极浅暖灰 | `#F8F9F8` |
| 卡片背景 | 白色 | `#FFFFFF` |
| 边线 | 低对比边界 | `#E9EEEA` |
| 圆角 | 轻量一致；不能每个组件独立选圆角 | 8px（控件），12px（卡片） |
| 间距 | 4px 基础标尺 | 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 字重 | 正文常规，标题强调，信息层级少而明确 | 400 / 600 / 700 |
| 图标 | 单一风格线框图标 | Lucide，16–20px |
| 动效 | 只表达状态与层级，不依赖炫技 | 120–180ms |

### 按钮统一规范

| 级别 | 适用 | 视觉 |
| --- | --- | --- |
| Primary | 新建、开始同步、提交研究等页面主目标；通常最多 1 个 | 深绿实底 + 白字 |
| Secondary | 导入、切换来源、返回、打开其他功能 | 白底描边 + 深灰字 |
| Tertiary | 查看全部、取消、辅助链接 | 无填充文字 / 图标 |
| Destructive | 永久删除、不可逆操作 | 危险色 + 二次确认 |
| Icon-only | 仅对图标语义很明确的轻量操作使用 | 34px 容器，`aria-label` + Tooltip |

**交互守则：** 按钮文字使用动词和目的（例如“导入 Markdown”“开始增量同步”）；避免“确定”“提交”一类脱离上下文的标签。长尾操作归入 `...` 菜单；危险操作不允许误点即生效。操作要具备 Loading / Disabled / Success / Error 状态。

## 6. 页面级重构方案

### 概览（新）
- 去掉纯装饰性大横幅，概况信息和最近文章进入首屏。
- 第一关注点：最近收录；第二关注点：常用主题与同步状态。
- 模块可进一步根据使用频率调整，但不引入几十个仪表盘组件。

### 文章库
- 顶部：标题 + 导入 + 同步（根据优先级只强化 1 个）。
- 第二行：统一搜索、主题筛选、排序、列表/卡片切换。
- 默认列表更适合密集的知识检索；卡片视图可切换，并记住偏好。
- 行内优先展示标题、摘要、主题、来源、时间；删除等低频危险动作放 `...`。
- 空态、分页、请求失败、批量选择，遵循同一组件规范。

### 阅读页
- 轻量返回、收藏/操作区，不重复展示大标题工具栏。
- 正文为视觉主角；本文目录与笔记、AI 助手收至可折叠上下文区。
- 选区后浮现最相关的操作（高亮、摘录、解释）；无选区时不展示选区专属命令。
- 保留来源追溯、原知乎链接、阅读记录、标注定位、笔记与 AI 历史。

### 话题汇总 / 主题目录
- 话题是“知乎问题聚合”，主题是“本地知识分类”，两种概念视觉和交互上明确区分。
- 话题页在内容之上提供轻量主题 chips，不再固定大目录抢空间。
- 主题页使用统一的分类卡片、二级主题管理与待整理队列；AI 分类入口集中，冲突分类由用户确认。

### 我的笔记 / 知识空间
- 笔记：左侧列表 / 右侧正文，创建、搜索、编辑、关联文章清晰可达。
- 知识空间：知识页树 + 文档正文 + 双向链接；Markdown 互通、持续研究放为次级模块。
- 优先保持文本可读性和连接关系可追溯，不滥用图谱视觉来替代编辑器。

### AI 研究
- 从问题输入开始，降低页面首屏复杂度。
- 明确区分“检索证据”“模型总结”“用户保存的研究笔记”。
- 答案显示引用链接和具体来源；无证据必须明确提示，不伪造引用。
- 历史、重试、取消、草稿恢复与发送隐私范围均保留。

### 同步中心与偏好设置
- 同步模式用两项清晰单选项；范围和本地存储路径明确可见。
- 任务详情以运行进度、成功、失败和重试为中心，错误信息可复制。
- 取消同步、续传、失败记录和账号扫码状态按真实后台能力实现，不靠装饰性进度条。
- 设置按“数据与连接”“模型与隐私”“外观偏好”分组，降低误操作风险。

## 7. 技术重构目标（确认设计后执行）

坚持 **保留现有 React/TypeScript、API 契约和后端数据结构**，优先重构前端架构与样式，不用不必要的技术迁移扩大风险。

```text
frontend/src/
├── app/
│   ├── AppShell.tsx
│   ├── router.tsx
│   └── providers/
├── design-system/
│   ├── tokens.css
│   ├── primitives/        (Button, Input, Dialog, Menu, Tabs...)
│   └── patterns/          (PageHeader, FilterToolbar, Table, EmptyState...)
├── features/
│   ├── overview/
│   ├── library/
│   ├── reader/
│   ├── questions/
│   ├── categories/
│   ├── notes/
│   ├── knowledge/
│   ├── research/
│   ├── sync/
│   └── settings/
├── shared/
│   ├── api/
│   ├── hooks/
│   ├── types/
│   └── utils/
└── main.tsx
```

建议使用 CSS Modules（或团队已有的等价隔离方案）+ 全局 Tokens。交互语义复杂的 Dialog、Menu、Popover 可以选成熟的无样式可访问性组件；保留已在使用的 Lucide。主题颜色、控件状态和尺寸统一由 Token 决定，不再单点覆盖全局 CSS。

### 建设顺序（阶段验收，不一次性推倒重写）

1. **基线冻结：** 核对 `main/dev`、可能存在的未推送分支和本地更改；提取完整路由截图、组件清单、API 调用与关键路径测试。
2. **设计系统：** Token、Button、Input、Select、Dialog、Dropdown、Tabs、Toast、Loading、EmptyState、ErrorState。
3. **应用骨架：** 左侧分组导航、顶栏、命令搜索、响应式；保留深链接和必要的工作标签状态。
4. **主链路：** 文章库 → 阅读 → 笔记，先做到最稳定、最完整。
5. **分类/话题/知识/AI：** 分批替换，同时兼容现有 API、任务状态和双链。
6. **同步/设置：** 覆盖登录、账号状态、全量增量、任务中断恢复、隐私和设置等风险较高场景。
7. **回归、无障碍、性能：** 视觉回归、键盘可达性、移动端、数据错误态；最后灰度切换。

## 8. 验收清单（用于确认后落地）

- [ ] 所有现有路由和深链接能正常访问；无丢失功能、无错误 API 映射。
- [ ] 桌面顶栏高度 ≤64px，导航不会遮挡内容；进入文章库首屏即可见真实文章。
- [ ] 核心页面操作只存在一个明显的 Primary 按钮；危险操作都有明确确认。
- [ ] 主题、来源、排序、搜索互相组合时结果正确；切换视图不丢失筛选状态。
- [ ] 文章正文、图片、Markdown 表格/代码块、引用来源和标注都正常。
- [ ] 多标签打开/切换、草稿提示、浏览器后退与恢复符合预期。
- [ ] 同步过程含成功/失败/重试/取消/断线/无数据/权限过期等状态。
- [ ] AI 研究引用可追溯；无证据不杜撰；用户清楚数据何时发送至模型。
- [ ] 390/768/1024/1440 宽度下没有横向溢出和不可触及的控件。
- [ ] 交互遵循 WCAG 2.2 AA 可达性目标：键盘顺序、焦点可见、语义标签、对比度。
- [ ] TypeScript 构建通过；必要的组件单测、Playwright 关键路径与截图回归通过。

## 9. 本次原型的范围与限制

**原型已覆盖：** 概览、文章库、文章阅读、话题汇总、主题目录、我的笔记、知识空间、AI 研究、同步中心、偏好设置；页面切换、列表/卡片视图、搜索、主题筛选、命令搜索（⌘/Ctrl + K）、明暗模式、笔记新增编辑、导入本地 Markdown 预览、AI 和同步的明确标识的模拟交互。

**原型没有完成：** 真实知乎登录及下载、数据库读写、实际 LLM 检索回答、全文 Markdown 渲染、生产级选区标注、真实用户数据、服务端持久化。这些都将在设计确认后由正式前端组件接入已有 API/服务。

**本轮明确不会执行：** 改动 GitHub 源码、创建或强推分支、删除旧功能、修改数据库、迁移资料库。

## 10. 确认重点

请重点评审以下设计决策：

1. 左侧导航：**“我的工作台 / 知识探索 / 工具设置”** 三段是否符合实际使用习惯？
2. 默认首页：是否采用轻量概览，而非直接进入文章库？
3. 阅读页：是否接受“正文优先 + 可收起右侧工具”的结构？
4. 视觉方向：低饱和松绿、近白底、轻描边是否合意？
5. 默认密度：列表优先，还是希望卡片优先？

在这五点明确后，再把设计系统和页面组件逐一落地到真实仓库。
