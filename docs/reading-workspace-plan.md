# 阅读高亮、批注、个人笔记与单篇 AI 阅读助手：实施方案

日期：2026-09-30。状态：拟实施方案，未实现。以当前源码为基础；本文不表示以下功能已经上线。

详细技术设计、SQL 草案和核心流程伪代码见 [详细设计文档](reading-workspace-design.md)。

## 1. 建议与目标

建议分两步交付：先完成“高亮 → 批注/个人笔记 → 搜索 → 回到原文”，再完成“单篇 AI 生成 → 自动保存 → 版本复用 → 转为个人笔记”。共用正文版本和位置锚点，避免两套功能分别处理定位与版本问题。

首版沿用本地 FastAPI、SQLite、React 和 Markdown 阅读器，不引入外部数据库、向量服务或新的模型供应商。一个熟悉代码库的全栈开发者，按约 18–22 个有效工作日安排，预留 3–5 日处理定位兼容和模型联调；这是工作量估算，不是交付承诺。

成功标准：

- 阅读时留下自己的理解，刷新和重启后仍可看到；中文搜索能够找到个人笔记。
- 点击批注或笔记的原文引用，可以定位到正确内容；无法确定时明确显示失效，不误定位。
- 全文总结、段落解释、提取要点都只使用当前这一篇文章的指定版本。
- 成功生成的 AI 结果自动保存；再次打开直接查看，需要重新生成时由用户主动触发。
- 文章同步、更新和分类不覆盖个人笔记；未配置模型及断网时笔记和历史结果仍可使用。

## 3. 首版产品范围

### 3.1 高亮和批注

- 选中正文显示浮动工具条：“高亮”“写批注”“解释这段”。支持桌面鼠标与移动端长按。
- 先提供三种颜色；允许修改颜色、删除高亮、为高亮增加一条可编辑批注。
- 批注必须保留选中文字和上下文；删批注可只清空批注文字，删整个高亮才删除该记录。
- 首版支持同一正文块内的普通文字，包括加粗、链接文本、行内代码；跨多个块的选择提示分段标注。图片、代码围栏、复杂表格、公式和隐藏内容暂不标注，但仍能写文章笔记。
- 同一段可以有重叠高亮；显示合并后的色带，点击后列出涉及的记录，不生成错误嵌套。

### 3.2 个人笔记

- 每篇文章可创建多条独立笔记，字段为可选标题和 Markdown 正文；与高亮无关也能写。
- 文章面板统一展示高亮批注和独立笔记，按更新时间排序，支持定位、编辑和删除。
- 独立“我的笔记”入口：搜索正文/标题/引用，按文章、分类和类型筛选，分页展示。
- 区分“我的文字”“原文引用”“AI 生成”，搜索命中不同区域时明确标注。
- 编辑停止约 800ms 后自动保存；显示“保存中 / 已保存 / 保存失败”，失败保留草稿与重试入口。
- 阅读页跳转时处理未保存草稿；浏览器本地保存带资料库标识、文章 ID 和版本的临时草稿，成功保存后清理。退出/切换资料库时不串用草稿。
- 每条记录有 `revision`，更新采用乐观并发控制；旧版本写入返回 409，允许复制草稿后重新加载，避免多标签页覆盖。

### 3.3 单篇 AI 阅读助手

| 操作 | 输入范围 | 输出结构 |
| --- | --- | --- |
| 总结全文 | 当前文章完整正文；长文逐段覆盖 | 一句话概括、主要论点、展开逻辑、适用条件/局限、原文引用 |
| 解释选中段落 | 选中文字及相邻有限上下文 | 通俗解释、术语说明、例子、上下文含义；区分原文与助手举例 |
| 提取要点 | 当前文章完整正文；长文逐段覆盖 | 默认 5–10 条，按原文组织，每条带原文位置，可选行动建议 |

- 用户点击后才调用模型。首次使用展示将发送的范围和当前提供方，记住启用选择；仅打开页面、写笔记、查看历史不触发外发。
- 成功结果自动保存为 AI 记录，可复制、删除、查看历史、重新生成和“保存为个人笔记”。
- 转存是新建可编辑个人笔记，保留来源结果 ID；编辑笔记不改动原始 AI 输出。
- 正文变化后，历史结果保留并标为“基于旧正文”；在新版正文上重新生成创建新记录。
- 未配置模型时显示设置入口，但已有高亮、笔记、历史 AI 结果照常阅读。
- 首版不加入开放多轮聊天、跨文章问答、笔记向量检索、图片理解、OCR、联网搜索或全文富文本编辑；这些可独立迭代，不作为本次依赖。

## 4. 阅读页交互

阅读页工具栏增加“笔记”“AI 助手”；与现有“文章信息”共用一个右侧面板，切换标签后仍保留编辑草稿。宽屏保持正文可读宽度，窄屏用底部抽屉。收起文章信息不能同时让个人笔记无入口。

高亮操作完成后出现记录卡：引用、批注、颜色、创建时间。点击记录先定位再短暂强调，不改变永久高亮色。定位失效时保留卡片并提供“重新选择原文”，不直接跳到可能错误的段落。

AI 面板顶部是三个操作和当前选区提示，下面显示生成进度及保存结果。重新生成期间继续展示已有结果。再次选择同一操作时优先打开已有有效结果，重新生成使用独立按钮，避免误耗额度。

“我的笔记”结果卡展示文章标题、类型、命中区域、摘要和时间；点击以 `/read/:id?annotation=:annotation_id` 或 `?note=:note_id` 打开并展开对应面板。保留文章库返回状态及原有图片交互。

## 5. 正文版本与高亮定位

### 5.1 正文版本

新增 `content_revisions`，按实际 Markdown 字节的 SHA-256 建立不可变版本，并保存原始 Markdown 快照、规范化文本、正文块和规范化协议版本。首版在第一次标注、生成 AI 或需要重定位时懒创建，不为全库预先复制正文。

- 前端阅读响应携带 `revision_id`、`body_hash`、`normalization_version` 和可标注块信息；创建标注、AI 请求都必须传入读取时的版本。
- 版本与文章关联，版本用于溯源，不能仅凭客户端传来的文字创建任意引用。
- 新同步只对正式采用的 `article.md` 登记版本；`article.remote.md` 冲突候选不触发重新定位或让 AI 结果失效。
- 本地文件手动改动在下次读取时发现；正文缺失时允许看笔记/历史结果，但禁用新全文生成。
- 已被标注或 AI 结果引用的版本不自动清理；可清理无引用版本。首版快照只保存文本，不复制每个历史版本的图片，历史图片完整恢复不在范围内。

### 5.2 锚点协议

不要保存 DOM XPath 或只保存段落序号。一个锚点至少包含：

- `revision_id`、`normalization_version`、`block_id` 与标题路径；
- 块内 `start` / `end`，使用 Unicode code point，而非 JavaScript UTF-16 单元；
- `exact` 原文、`prefix` / `suffix` 上下文（初始各取约 32 字，可根据歧义扩展）；
- 块文本哈希和定位状态。

后端正文块解析与前端 Markdown AST 映射遵守同一套文本投影规范：文字与行内代码保留内容，链接保留显示文字，格式标记和图片不计入偏移；换行规则固定，不随意压缩空格。使用共享 JSON 夹具核对中文、emoji、实体转义、软换行和嵌套行内节点的一致性。实现第一天做定位原型，确认现有净化/渲染管线可保留安全的块标识。

创建锚点时后端校验范围、块和 `exact`，客户端无法伪造不属于该正文的引用。渲染通过 AST 文本映射生成安全标记节点，不直接修改 React 管理的 DOM，也不把笔记写回原始 Markdown。

### 5.3 正文变化后的重定位

1. 当前版本与原版本一致：校验偏移及原文后定位。
2. 版本不同但原块内容仍存在：在新块中检验原文和上下文后定位。
3. 搜索新正文中的 `exact`，结合前后文、标题与块哈希，仅在唯一且证据充分时迁移。
4. 多个候选或原文消失：标记 `ambiguous` / `orphaned`，不做模糊自动迁移。
5. 人工重新绑定生成新的当前定位记录，但保留创建时的原始版本和引用；正文切换触发幂等重定位。

原始锚点不可变，当前锚点单独保存，避免多次同步后失去出处。对大量标注按文章和版本排队重定位，阅读时先显示状态，避免阻塞整个列表。

## 6. 数据模型与存储

SQLite 是个人数据的唯一权威来源。正文继续存现有文件，个人笔记不塞入 `metadata.json`，防止同步覆盖。个人数据与文章一起放在用户选择的资料目录，不放项目仓库。

| 表 | 核心字段和约束 |
| --- | --- |
| `content_revisions` | `id`, `content_id`, `body_hash`, `markdown_snapshot`, `normalized_text`, `blocks_json`, `normalization_version`, `created_at`；文章+哈希+规范化版本唯一 |
| `annotations` | `id`, `content_id`, `original_revision_id`, `original_anchor_json`, `current_anchor_json`, `anchor_status`, `color`, `comment_md`, `revision`, 创建/更新时间 |
| `notes` | `id`, `content_id`, `title`, `body_md`, `origin_ai_result_id`（可空）, `origin_metadata_json`, `revision`, 创建/更新时间 |
| `reading_ai_jobs` | `id`, `content_id`, `revision_id`, `action`, `selection_anchor_json`, `input_manifest_json`, `config_fingerprint`, `prompt_version`, `reuse_key`, `request_key`, `status`, `stage`, `progress`, `cancel_requested`, `error_code`, 时间戳 |
| `reading_ai_job_steps` | `id`, `job_id`, `step_no`, 输入块/哈希、状态、结构化中间结果、尝试次数；任务+步骤唯一，用于长文恢复 |
| `reading_ai_results` | `id`, `job_id UNIQUE`, `content_id`, `revision_id`, `action`, `selection_anchor_json`, `result_json`, `rendered_md`, `citations_json`, 提供方/模型、提示词/配置版本、可获取的用量、生成时间 |
| `note_search` | FTS5 trigram：记录 ID 和类型不索引；用户标题、用户文字、原文引用、关联文章标题分列 |

补充约束：

- 所有个人记录关联真实 `contents.id`。版本与内容 ID 的一致性由约束/服务校验保证；AI 结果引用真实版本和任务。
- `content_id` 外键级联删除个人记录，FTS 记录显式清理；删除文章确认框展示高亮、笔记和 AI 记录数量，并提示先导出。删除失败要保留可恢复数据，避免先删除个人记录再发生文件错误。
- 笔记到 AI 结果的外键用 `ON DELETE SET NULL`；来源摘要快照保留，删除 AI 结果不删除转存的个人笔记。
- 删除高亮会删除其批注，文章级笔记不受影响；删除 AI 历史结果不影响其他结果。
- 不允许删除仍被引用的正文版本；删除文章时按明确顺序在事务内清理结果、标注和版本。
- 对内容 ID、创建时间、任务状态、结果复用键加普通索引；笔记更新和 FTS 更新同事务完成。
- 更新文章标题时更新笔记索引中的关联标题，分类筛选通过当前文章关系关联，不复制易过期的分类名。

### 6.1 迁移、导出和恢复

当前连接函数包含建表与检查字段逻辑。新增显式、幂等、事务化的 schema 迁移入口，在启动和资料库切换时执行；旧资料库迁移前用 SQLite backup API 创建一致备份，不能直接复制运行中的 WAL 主文件冒充备份。

首版提供单篇导出：可读 Markdown（批注、笔记、AI 结果标识）及机器可恢复 JSON（schema 版本、版本快照、锚点、记录及来源）；恢复支持导出文件 ID 去重、关联存在性验证和先预览后写入。全文/个人数据均视为私人资料。全库可靠备份仍是整个资料目录加一致数据库备份；导出失败不回滚已成功保存的笔记。

切换资料目录视为切换资料库，不是自动迁移。活动 AI 任务期间拒绝切换并提示先完成/取消；任务始终绑定启动时的资料库路径和配置，不能随后读写新的目录。需要移动资料库时停止任务，按备份恢复流程操作。

## 7. 搜索设计

“我的笔记”使用独立 FTS5 trigram，沿用当前数据库已有能力。对三字以上查询走经过转义的 FTS；单字/双字和特殊符号走参数化子串回退，避免中文短词无结果或 FTS 语法异常。明确 `%`、`_`、引号的字面语义。

索引包含独立笔记、批注及高亮引用；默认只搜索用户文字和标题，用户勾选“包含原文引用”后加入引用列。AI 结果独立历史入口按操作/时间筛选，首版不混入个人笔记搜索；转为笔记后纳入搜索。

支持 `q`、`type`、`content_id`、`category_id`、`include_quotes`、`page`、`page_size`；按匹配程度和更新时间稳定排序。片段高亮用安全文本节点，禁止把 FTS 的标记字符串直接当 HTML 渲染。索引可从权威记录重建，提供迁移与删除后的完整性检查。

性能目标：在同一台记录配置的开发机，用生成的 10,000 条笔记测量，常规搜索 P95 ≤ 500ms；短词回退单独记录。该指标是验收目标，达不到先根据执行计划优化，不预先引入外部搜索系统。

## 8. AI 执行、复用和溯源

### 8.1 输入与模型适配

新增阅读助手服务，复用 `chat_completion`，不调用跨库 `retrieve()`。正文由服务端从指定快照读取，段落解释只发送已校验选区及有限相邻上下文。

配置增加上下文窗口、输入安全预算、最大输出、超时与并发上限；为提供方记录可用能力。实际上下文能力未知时使用保守估计和余量，遇到超限再缩小块重试，不固定用字符数冒充 token 数。模型标识或供应商变化不影响查看旧结果。

现有 OpenCode 适配不保证传递 `max_tokens` 或返回 token 用量；扩展适配层时明确这些能力差异。无法取到用量记为未知，不能编造花费。OpenCode 本机命令可能连接云模型，界面不得把它一概描述为离线处理。

### 8.2 长文不能静默截断

- 在预算内：一次发送全部文本块和后端分配的引用 ID。
- 超过预算：按标题/段落切分，所有块进入分段分析；持久保存中间步骤，再进行分层归并。
- 归并阶段继续检查预算，保持已校验的原始块引用映射，不能只保留没有出处的摘要。
- 要点提取先分段提取、再去重和组织；总结先分段总结、再归并成全文结果。
- 输入清单记录正文块总数、已处理数和覆盖范围。只有完整覆盖才返回“全文”成功；任一块失败则任务失败，可保留中间步骤重试，不发布残缺全文总结。
- 极长文章达到配置的调用/费用上限时，在执行前提示限制及可选范围；选范围的结果明确命名为“选定范围总结”。

进度展示“准备 → 分段分析 x/y → 汇总 → 校验 → 已保存”。首版用任务轮询，不要求模型流式响应，避免现有两个适配器能力不同阻塞交付。

### 8.3 结果结构与引用

模型输出按操作分别用 Pydantic 校验：例如摘要包含概括、论点列表、局限与引用；要点包含正文和引用 ID 列表。兼容不能原生输出 JSON 的提供方，使用文本 JSON 解析与最多一次格式修复，仍失败返回明确错误，不保存成成功结果。

引用 ID 由后端生成并映射到版本中的真实块/选区。出现不存在的 ID 拒绝该输出并进行有限修复；重要结论缺少引用时不能显示为已验证结论。历史结果点引用默认打开对应旧版本文本预览，可另尝试定位新版；不能把旧结论冒充新版正文结论。

引用有效只说明位置确实存在，不证明模型理解正确；生成卡持续标注“AI 生成”，用户可检查原文。原文中的命令、系统提示或链接一律当数据处理，助手无执行工具权限，不读取其他文章、凭据或本机文件。

### 8.4 自动保存与复用

复用键包含：资料库标识、文章 ID、正文版本、操作、解释选区的精确锚点、输出语言/选项、提供方/模型/相关生成配置指纹、提示词版本。

- 默认请求先查匹配的成功结果，命中即返回该结果，不调用模型。
- 同复用键已有排队/运行任务时返回该任务；用数据库约束实现去重，不依赖内存布尔变量。
- “重新生成”使用 `force=true` 新建历史结果，但同一客户端请求的重复发送通过 `request_key` 去重。
- 结果保存与任务置为成功同事务完成；前端刷新或离开阅读页不会丢失后台结果。
- 保存已完成但响应丢失时客户端按任务 ID 找回，不重新请求模型。
- 输入版本和配置在任务创建时固定；正文更新后结果仍归旧版本，前端标明过期。密钥不进入任务表、日志、导出或配置指纹。

### 8.5 任务与失败恢复

状态机：`queued → running → completed | failed | cancelled | interrupted`。首版每个资料库默认一个阅读任务执行、有限队列，不阻塞同步/普通阅读；数据库事务不得包住模型网络请求。

超时、网络错误、额度不足和格式错误分别给出稳定错误码。只对暂时性故障做有上限退避；额度不足、未配置和无效输入不自动重复扣费请求。取消后丢弃后续返回、不保存新成功结果，关闭 OpenCode 子进程并处理资源。

进程重启将进行中的任务标记 `interrupted`，由用户重试；已成功分段步骤可复用，处于未知完成状态的远程调用可能已经计费，重试按钮说明这一具体情况。跨崩溃无法承诺提供方调用恰好一次。

文章删除时取消关联任务，写回前再次检查文章是否存在；与现有内容写锁协调，防止删除后任务把记录重新建回来。运行任务期间更改模型配置只作用于新任务；旧任务继续使用内存中的已捕获配置。

## 9. API 草案

统一置于现有 `/api/v1` 前缀，保持现有文章、分类和 `/ask` 契约。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /contents/{id}/reading-context` | 返回实际正文版本、块映射、标注状态；与正文读取保持同一快照 |
| `GET/POST /contents/{id}/annotations` | 获取/创建高亮与批注 |
| `PATCH/DELETE /annotations/{id}` | 修改文字/颜色或删除，PATCH 必须带 revision |
| `POST /annotations/{id}/reanchor` | 按用户新选区人工重新绑定 |
| `GET/POST /contents/{id}/notes` | 获取/创建文章笔记 |
| `PATCH/DELETE /notes/{id}` | 修改/删除笔记，PATCH 必须带 revision |
| `GET /notes/search` | 分页搜索个人笔记、批注，支持引用开关与筛选 |
| `POST /contents/{id}/reading-ai-jobs` | action、revision_id、可选锚点、force、request_key；返回已有结果或 202 任务 |
| `GET /reading-ai-jobs/{id}` | 查询进度、稳定错误码、结果 ID |
| `POST /reading-ai-jobs/{id}/cancel` | 协作式取消 |
| `POST /reading-ai-jobs/{id}/retry` | 按固定输入重试，保留原任务历史 |
| `GET /contents/{id}/reading-ai-results` | 按操作分页读取历史 |
| `GET/DELETE /reading-ai-results/{id}` | 读取/删除保存结果 |
| `POST /reading-ai-results/{id}/notes` | 幂等转存为个人笔记 |
| `GET /contents/{id}/revisions/{revision_id}` | 读取授权范围内的历史正文文本 |
| `GET /contents/{id}/reading-export?format=` | 单篇 Markdown/JSON 导出 |
| `POST /reading-imports/preview`、`POST /reading-imports` | 恢复前验证与预览，随后提交 |

输入限制建议：每条笔记 100KB、批注 20KB、解释选区 8,000 字；正文/任务总预算独立控制。限制在前后端一致展示，并可根据实测调整。不存在返回 404、版本过期/并发冲突 409、输入无效 422、模型未配置 503、提供方失败用任务错误状态。错误返回不泄漏提供方响应里的密钥和正文。

## 12. 测试与验收清单

### 12.1 必须自动化的行为风险

1. **迁移**：带文章/分类/旧 FTS 的数据库升级、重复启动、升级失败回滚、一致备份及目录切换。
2. **锚点**：中文、emoji、重复段落、软换行、链接/加粗/行内代码、块前插入、引用删除、歧义、净化导致结构变化；前后端夹具一致。
3. **笔记**：版本冲突不覆盖、保存和 FTS 事务、删除后搜索无残留、批注/笔记区分、同步更新不改用户文字。
4. **搜索**：中文单字/双字/长词、引号/百分号/下划线、范围过滤、稳定分页、重建结果一致。
5. **AI**：只读取指定文章/版本；未配置不调用；选区必须来自正文；正常/长文完整覆盖；非法引用拒绝；格式错误、超时、限额、局部失败。
6. **复用与恢复**：复用键变化、双击并发、force 请求重复发送、响应丢失、刷新、重启、取消、部分步骤重试。
7. **竞态与边界**：同步时正文更新仍按快照生成；删除后任务不回写；切换资料库不串数据；路径穿越/XSS；密钥不进入持久任务/导出。
8. **导出恢复**：schema 校验、重复导入去重、缺少文章时明确处理、锚点和 AI 来源保持一致。

模型单元/集成测试用 stub 校验输入范围、调用次数、结果保存和失败恢复，不依赖付费模型。真实提供方联调另记版本和响应能力，不能用 stub 通过声称真实模型已经兼容。

### 12.2 人工端到端验收

- 收藏文章 → 高亮 → 写批注 → 加个人笔记 → 刷新/重启 → 搜索 → 回到原文。
- 修改正文，在段落前插入内容 → 定位仍正确；删除引用 → 显示失效 → 人工绑定恢复。
- 短文执行三个 AI 操作 → 历史结果离线可看 → 重复点击不调用 → 主动重新生成出现新版本。
- 长文的后半部分包含独有论点 → 总结/要点能够覆盖；中间块失败不能显示全文成功。
- 结果转存笔记后修改 → 原 AI 结果保留 → 删除 AI 结果后个人笔记仍在。
- 网络断开/额度不足/取消/重启 → 错误和重试明确 → 已保存内容不消失。
- 桌面和窄屏测选区工具条、抽屉、键盘操作、保存状态、重叠高亮及长结果。
- 单篇导出并恢复到测试资料库，核对记录数、文字、原文位置、版本和来源。

回归命令：`cd backend && .venv/bin/python -m pytest`；`cd frontend && npm run build`。实施时补充实际采用的前端测试命令；视觉变更提供截图。最终报告记录执行结果和未验证的真实提供方，不把“拟实施”改写成“已完成”。
