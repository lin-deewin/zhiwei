# 知乎接入能力记录

## 当前状态（2026-09-29）

旧网页接口二维码流程曾成功获取令牌和链接，但 `scan_info` 返回错误码 `40352`，要求安全验证，因而未完成扫码登录。旧流程参考了 [zhihu-cli](https://github.com/BAIGUANGMEI/zhihu-cli) 的公开实现。普通 Google Chrome 曾通过人工验证成功连接账号，Playwright Chromium 在当时的环境中停留在安全验证页。新入口改为通过 Xvfb 运行普通 Chrome，直接在知微页面展示其登录画面；这不保证知乎放行当前服务器。

新页面内登录入口已在没有 `DISPLAY` 的隔离环境中启动 Xvfb 与普通 Chrome，并抵达知乎安全验证页；知微弹窗可显示该页面并提供受限人工输入。2026-09-29 在该页面点击“开始验证”后，浏览器向 `captcha.zhihu.com/api/v1/captcha` 发出的请求收到 HTTP 403，页面因此显示“正在加载，请稍后重试”。点击操作已传达到知乎页面；验证码服务拒绝当前服务器请求。真人验证及后续二维码扫码闭环仍未完成，因此不能将新流程记为已验证可用。

同日，从服务器原有的普通 Chrome 私有配置目录恢复了此前由账号本人完成验证的有效会话，保存为权限受限的会话快照。后端重启后再次验证账号成功，刷新收藏夹接口返回两个收藏夹。这证明已有会话的恢复与收藏夹读取可用，不证明当前服务器能完成新的验证码及扫码登录。

扫码和浏览器会话现在都可用于收藏夹列表及同步请求，后端会创建真实任务并将读取到的文章或回答保存为 Markdown。收藏夹条目若只有摘要，后端会按文章或回答 ID 补读详情。当前环境已通过普通 Chrome 完成真实账号验证，读取到两个收藏夹，全量同步已连续扫描并保存超过 100 条且当时失败数为 0；完整任务结果、回答及图片字段仍需继续核对。如果知乎返回不同格式，任务会失败并显示原因。不会生成模拟成功记录。
